# 棋谱变着树浏览 设计方案

日期：2026-09-30
实现计划：`2026-09-30-variation-tree-implementation.md`

## 1. 背景与目标

现状：棋谱以 `Game` 为单位线性存储（`games.moves` + `games.initial_fen`），移动端浏览是单盘棋的逐步回放（`MobileHomeView` 的 `moves`/`ply`），没有跨棋谱的变着导航。而一个棋谱集（`category = "古谱 · X"`）里的多盘棋往往在同一局面后分叉，用户希望浏览到某局面时能直接按变着继续。

目标：

- 同一棋谱集内，把彼此到达**同一局面**的棋谱视为一张**局面图**；在分叉局面提供变着入口，选中后沿该分支继续浏览。
- 淡化「当前是哪盘棋」的边界：浏览会话是一条路径，可在任意节点切换分支，变着递归出现。

非目标：

- 单盘棋谱内部的分支（`moves` 仍线性）。
- 显式归属 / 分组：本方案完全由局面自动判定（阈值规则见 §2），不引入父子边或专题表。

## 2. 判定规则

- **节点** = 局面，key `fen_key` = FEN 的**布局段 + 行棋方段**（本实现 `to_fen` 末尾固定 `- - 0 1`，取前两段即可）。
- 节点身份**与到达路径无关**：不同着法顺序（转置）、不同着法数量（步数差为偶数、行棋方相同）到达同一局面，视为同一节点。
- **边** = 一步着法（`from_fen --move--> to_fen`）。
- 构图范围：**同一棋谱集**（`category` 相同且非空，即 `古谱 · ` 前缀）内的棋谱。
- **分叉入口**需同时满足：
  1. 该节点出度 ≥ 2（存在不同的下一步）；
  2. **经过该节点的每一盘棋谱在该节点的步数都 `> 4`**（严格大于；4 着 = 双方各 2 步）。只要有一条谱以 ≤ 4 着经过该节点，就不算分叉。
- **变着** = 该节点的其他出边。一条边（`from_fen` + `move`）可关联多盘谱（同着法合并）。
- **浏览会话 = 路径栈**：到达分叉入口弹出分支选择器，选中即压栈，返回即弹栈。

阈值 `4` 作为可配置常量（默认 4），后续可按集调整。

## 3. 数据模型

新增派生索引表 `game_steps`（可随时重建）：

| 列 | 说明 |
|---|---|
| `collection` | 棋谱集名（`category` 去掉 `"古谱 · "` 前缀） |
| `game_id` | 所属棋谱 |
| `ply` | 行号（0-based，表示「走该步之前」） |
| `fen_key` | 走该步之前的局面 |
| `move` | 该步坐标，文本 `x1,y1,x2,y2`（`Move` 无 ICCS，用坐标作分组键） |
| `next_fen` | 走该步之后的局面 |

索引：`(collection, fen_key)`、`(collection, next_fen)`、`(game_id)`。

- 节点 P 在某谱中的步数：P 作为 `next_fen` 时取 `ply + 1`；P 等于该谱 `initial_fen` 时取 `0`。
- 重建：`create_game` / `update_game` / `import_pgn` / `delete_game` 后重建该谱的行；另提供 `scripts/rebuild_game_steps.py` 全量重建。
- 建表沿用 `app.py::_ensure_schema` 的 `CREATE TABLE IF NOT EXISTS` 模式。

## 4. 后端接口

`POST /api/games/collections/children`

请求体：`{ "collection": "<集名>", "fen": "<完整 FEN>" }`

响应：

```json
{
  "fen": "rnbakabnr/... w - - 0 1",
  "branchable": true,
  "plies": { "min": 5, "max": 9 },
  "branches": [
    {
      "move": { "x1": 1, "y1": 7, "x2": 4, "y2": 7, "iccs": "b7e7", "chinese": "炮二平五" },
      "to_fen": "...",
      "games": [{ "id": 88, "name": "..." }],
      "end_games": []
    }
  ]
}
```

- `branchable` 由后端按 §2 判定（出度 ≥ 2 且所有经过谱 `ply > 4`），前端直接采用，避免口径歧义。
- `plies` 为经过该节点的各谱步数区间，供 UI 展示。
- `branches` 按 `(from_fen, move)` 合并；`games` 列出用到该边的谱，`end_games` 为走完这步后即结束的谱。
- `fen` 不属于该集任何谱的局面时，返回空 `branches`、`branchable=false`。
- 错误沿用 `{ "error": "...", "detail"?: "..." }`。

（可选，后续）`POST /api/games/collections/tree` 小集全量返回，前端翻步零请求。

## 5. 前端改造

- 状态升级：`moves` 从「当前棋谱着法」变为「**当前路径**着法」（可跨谱）；`ply` 为路径长度；新增按 `fen` 的 children 缓存。
- 进入棋谱集：以所选棋谱的 `initial_fen` + `moves` 作为初始路径（等价于在图上走一遍）。
- 每次路径变化后查询当前 `fen` 的 children（带缓存）；`branchable` 为真时在 `BoardControls` 显示「变着 n」入口。
- 变着弹层（新组件，复用 `MobileGamePicker` 卡片样式）：列出各分支的着法中文、来源谱、是否末步。
- 选择分支：`moves = moves.slice(0, ply)`，push 该分支 `move`，`ply += 1`；随后按新节点 children 决定是否自动前进（唯一出边可自动继续，多出边弹层）。
- 路径条 / 面包屑：显示已走着法序列，可点击回退到任意步。
- 背谱 / 复习：**仍以 `Game` 为单位**（SRS、掌握度、错题绑定不变）。树浏览中维护 `currentGame`：默认取初始进入的谱；切换分支时更新为所选分支 `games` 的代表（如后续最长者）。进入背谱时以 `currentGame` 为准，用户也可从列表另行选择。

## 6. 边界与取舍

- **阈值 4 偏短**：完整职业对局集中，两盘棋共享前 4~10 着很常见，会被连成变着；本规则更适合古谱 / 排局 / 专题集。必要时调高阈值或按集配置。
- **转置 / 合流**：节点可能多入多出；路径栈记录实际走法，节点不存「深度」。
- 合流不算分叉：只有出度 ≥ 2 才弹变着。
- 仅 `category` 非空（`古谱 · ` 前缀）的棋谱集参与；赛事 / 其它不参与，避免跨集误连。
- 空集 / 单谱退化为单谱浏览。
- 性能：`children` 为一次索引查询；重建为 O(集内总步数)。大集可后续改全量缓存。

## 7. 测试要点

- 后端：同集两盘前 5 着相同、第 6 着分叉 → 分叉点 `branchable=true` 且两条 `branches`；前 4 着即分叉 → `branchable=false`；转置（不同顺序到达同一局面）合并为同一节点；跨集不关联；单谱退化为无变着。
- 前端：路径栈推进 / 回退、变着弹层选择后路径正确、唯一出边自动前进、children 缓存命中。

## 8. 实施阶段

1. **后端**：`game_steps` 索引表 + 重建脚本 + `children` 接口 + pytest。
2. **前端**：树浏览路径栈 + 变着 UI + vitest + `npm run build`（AGENTS 要求）。
3. **衔接**：背谱入口与 `currentGame` 语义打磨。
