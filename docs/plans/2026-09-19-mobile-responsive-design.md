# 移动端适配设计（移动优先重构）

日期：2026-09-19

## 目标

将现有 Web 前端重构为**移动优先**：以手机竖屏（≤480px）为默认基准，桌面端（≥768px）作为增强，视觉维持现状。核心是让所有页面在手机上可用、舒适：不溢出、触摸目标够大、布局单列堆叠。

## 现状问题

- `EditorView` / `PracticeView` / `ReviewView` 使用固定列宽 `grid-template-columns: 528px 1fr`（或 560px），手机竖屏必然横向溢出。
- `LibraryView` 用 `<table>`，窄屏列挤压。
- 顶栏导航为桌面式横向布局。
- 输入框字体可能 <16px，触发 iOS 聚焦自动缩放；按钮触摸目标偏小。

## 设计决策

1. **移动优先 + 媒体查询增强**：默认样式面向手机；`@media (min-width: 768px)` 恢复双列/表格等桌面布局。
2. **尽量只改 CSS，保持 DOM 稳定**：响应式表格用 CSS `display:block` + `::before` 标签实现卡片化，不替换 DOM，确保现有 66 个前端测试不回归。
3. **移动端底部 Tab 导航**：`App.vue` 增加底部导航（棋谱库 / 录入 / 复习），移动端显示、桌面端隐藏；桌面端顶部导航移动端隐藏。
4. **安全区适配**：`env(safe-area-inset-*)` 适配刘海屏与底部横条。
5. **触摸优化**：按钮/输入最小高度 44px、字体 ≥16px、`-webkit-tap-highlight-color: transparent`、`touch-action: manipulation`。

## 各页面方案

| 页面 | 移动端（默认） | 桌面端（≥768px） |
|---|---|---|
| App | 底部 Tab 导航；main 内边距含安全区；底部预留导航高度 | 顶部导航栏 |
| ChessBoard | 占满宽度等比缩放 | 限制最大宽度 |
| Library | 表格行 → 卡片（字段名用 `::before`）；工具栏纵向堆叠；按钮加大 | 表格 |
| Editor | 单列（棋盘上、表单下） | 双列 |
| Practice | 单列（棋盘上、控制/着法下） | 双列 |
| Review | 单列；控制按钮大号 | 双列 |

## 实现方式

- 各组件 `<style scoped>` 内改为移动优先写法，桌面增强放进 `@media (min-width: 768px)`。
- `App.vue` 的导航改为「移动底部 + 桌面顶部」两套，用媒体查询切换显示。
- 统一触摸目标尺寸与字体下限。

## 验证

- 前端全量测试（66 个）保持通过；`npm run build` 成功。
- 用 Python Playwright（环境已具备 chromium）以移动视口（如 390×844）与桌面视口（1280×800）分别截图首页、棋谱库、录入、打谱、默写，人工核对无溢出、布局正确。

## 不在本次范围

- PWA / 离线 / 添加到主屏。
- 移动端专属交互（手势拖动走子等）。
- 平板断点的精细调优（手机为主，768px 以上按桌面处理）。
